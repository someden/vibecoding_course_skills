# Vibecoding Course Skills

Переносимый набор скиллов курса: общие инструкции в `skills/`, промпты четырёх ролей
в `agents/`, поставка для Claude Code через `.claude-plugin/`, для Codex и OpenCode
через Agent Skills CLI. Исследования и материал для статьи — в `docs/`.

## Изменение скиллов

- Скиллы применяются в чужих проектах. Стек, команды, домен и сущности определяются
  из целевого проекта, а не из этого репозитория.
- Общие правила исполнения клиентов — `skills/_shared/runtime.md`. Каждый скилл
  читает их через `references/runtime.md`. Различия API не размазывать по процессам.
- Общие справочники хранятся в `skills/_shared/`, роли — в `agents/`. Внутри скилла
  нужны относительные symlink на используемые ресурсы: `references/<файл>.md` и
  `agents/<роль>.md`. Редактировать источник один раз; не поддерживать ручные копии.
- Все ресурсы должны входить в установленный каталог отдельного скилла. В его тексте
  ссылаться на локальные `references/` и `agents/`, а не на соседей через `../_shared/`
  или корень репозитория. Справочник ссылается на другие ресурсы относительно себя.
- Подагенту вызывающий скилл передаёт абсолютные пути к нужным ресурсам. Статические
  пути машины автора в инструкции не попадают.
- `description` описывает действие и условия запуска, не содержит относительных путей
  и укладывается в 1024 символа. Процедура и ограничения остаются в теле/справочниках.
- Зависимости от других скиллов перечислять явно; упоминание имени не устанавливает
  зависимость автоматически. Рекомендация следующего шага не является зависимостью.
- Инструменты подбирать под бюджет человека: правило `skills/_shared/constraints.md`,
  ограничения — в слое 2 спеки. Уже оплаченное → бесплатное → дешёвое → платное.
- Сохранять границы задач, независимую проверку, согласования и ограничения повторов.
  Установка файлов не доказывает работоспособность процесса в клиенте.

## Проверка

- `python3 scripts/check_skills.py` — метаданные, ссылки, ресурсы изолированных скиллов
  и манифесты. После изменения упаковки также проверить реальный CLI во временном
  проекте по инструкции в `docs/portability.md`.
- После изменения скриптов запускать их; проверять наблюдаемые свойства поставки,
  а не совпадение формулировок Markdown.

## Версии

- Версия плагина меняется только в `.claude-plugin/plugin.json`.
- `metadata.version` в `.claude-plugin/marketplace.json` — версия каталога, её не
  поднимать без явной просьбы пользователя и не синхронизировать с версией плагина.
- Описания манифестов обновлять по фактическому составу.

## Git

- Работать в `main`. Новую ветку создавать только по явной просьбе пользователя.
- Ничего не коммитить без явной просьбы пользователя.
