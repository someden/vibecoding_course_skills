# Переносимость набора

Состояние реализации и проверок: 26 сентября 2026 года. Версия Claude-плагина — 0.8.0.
Изменения рабочей копии нужно опубликовать, прежде чем они станут доступны при установке
по имени GitHub-репозитория. Для локальной проверки используется путь к checkout.

## Один источник, два способа поставки

Содержимое `skills/` общее для Claude Code, Codex и OpenCode. Claude-плагин сохраняет
существующий marketplace. Skills CLI устанавливает весь набор или выбранные скиллы
в каталоги клиентов. Отдельные нативные плагины Codex/OpenCode и генератор TOML-агентов
для этого варианта поставки не нужны.

Общие материалы редактируются в `skills/_shared/`, роли — в корневом `agents/`.
У использующего их скилла есть локальные относительные ссылки:

```text
skills/run-task/
  SKILL.md
  references/
    runtime.md -> ../../_shared/runtime.md
    task-format.md -> ../../_shared/task-format.md
    report-format.md -> ../../_shared/report-format.md
  agents/
    implementer.md -> ../../../agents/implementer.md
    task-verifier.md -> ../../../agents/task-verifier.md
```

Все ссылки остаются внутри репозитория/Claude-плагина. Текст скилла обращается к
`references/task-format.md`, а не к отсутствующему после выборочной установки соседу.
В Skills CLI 1.5.25 вложенные symlink при копировании разворачиваются в обычные файлы.
Следовательно, исходники не дублируются вручную; установленные автономные скиллы
получают собственные копии нужных материалов. Между клиентами CLI по умолчанию
использует общий установленный каталог и ссылки там, где они требуются.

Каталог отдельного скилла содержит его ресурсы, но не другие скиллы. Зависимости
оркестраторов перечислены в их разделах «Зависимости» и в [README](../README.md).
Skills CLI не устанавливает их автоматически только по этому тексту. Полная установка
набора остаётся самым простым вариантом для курса.

## Что адаптировано

- У всех 31 скилла короткие описания с условиями запуска, не длиннее 1024 символов.
  Процедуры, лимиты повторов и правила приёмки остаются в теле.
- Подсказки аргументов перенесены из Claude-поля `argument-hint` в тело 17 скиллов:
  общий frontmatter проходит штатную проверку Codex. Аргументы остаются прежними,
  но отдельная подсказка в меню Claude теперь не задаётся этим полем.
- Каждый скилл читает [общий справочник среды](../skills/_shared/runtime.md).
  Он описывает поиск и вызов скиллов, вопросы с ожиданием ответа, подагентов,
  продолжение сессий, проектные пути и поведение при недоступных возможностях.
- Вызовы жёстко заданных Claude-типов заменены делегированием с промптом роли.
  В Claude-плагине корневые роли по-прежнему могут регистрироваться нативно;
  при установке через Skills CLI используется доступный обычный подагент.
- `run-task` сохраняет идентификатор исполнителя, запускает проверяющего без истории
  исполнителя/оркестратора и проверяет его изменения относительно снимка перед проверкой.
  Код исполнителя в общем diff больше не принимается за нарушение проверяющего.
- `init-project` создаёт общие правила в `AGENTS.md` и мини-скиллы в `.agents/skills/`;
  Claude подключается импортом правил и ссылками на мини-скиллы. Существующие настройки
  сначала обнаруживаются и сохраняются. Память клиента необязательна.
- Правило `.gitignore` для артефактов перенесено в общий формат задач: отдельному
  `run-task` больше не нужен файл другого скилла ради этого фрагмента.
- Правила разработки самого набора живут в корневом `AGENTS.md`; `CLAUDE.md` импортирует
  его. Эти файлы предназначены для сопровождения репозитория и не служат скрытой
  зависимостью установленных скиллов.

## Ограничения, которые не скрывает адаптер

Для `run-task` нужны отдельный проверяющий и возможность продолжать исполнителя.
Клиент без этих возможностей не выполняет полный цикл: до начала изменений он сообщает
об ограничении, а при потере сессии в процессе задача получает `needs_human`.
Критика спеки и плана также требует отдельного участника. У `ai-ideas` сохранён его
явный запасной вариант: самостоятельная критика с сообщением об отсутствии подагента.

Ограничения `tools` во frontmatter ролей — нативные настройки Claude Code. При передаче
тела роли обычному подагенту они автоматически не становятся разрешениями другого
клиента. Адаптер использует доступный профиль без записи, когда он есть; иначе запрет
редактирования остаётся инструкцией, проверяется по результату и не называется sandbox.
Для обязательной технической изоляции потребуется отдельная настройка конкретного клиента.

Вопрос можно задать обычным текстом, если специальный инструмент недоступен. Обязательный
ответ при этом по-прежнему нужен. Разрешение на работу, приёмка, коммит и публикация
учитываются в пределах поручения пользователя; миграция не выдаёт новых разрешений.

В исходном checkout должны сохраняться symlink. Копирование текста ссылки в обычный файл,
особенности ZIP или отключённые symlink в Git на Windows не дают эквивалентную поставку.
Используй проверенный установщик и проверяй конечное дерево после изменения упаковки.

## Воспроизводимые проверки

Быстрая проверка репозитория, Python 3.9+ без сторонних зависимостей:

```bash
python3 scripts/check_skills.py
```

Она проверяет принятый в репозитории плоский frontmatter, имена и длины описаний,
манифесты, целостность ссылок. Каждый скилл копируется отдельно с разыменованием ссылок;
ссылки на ресурсы затем проверяются уже внутри изолированной копии. Это не универсальный
YAML-валидатор и не доказательство поведения модели.

Реальная проектная установка во временный каталог, без изменения глобальных скиллов:

```bash
VIBE_SOURCE="$PWD"
VIBE_CASE="$(mktemp -d)"
cd "$VIBE_CASE"
DISABLE_TELEMETRY=1 npx skills@1.5.25 add "$VIBE_SOURCE" --skill '*' --agent codex opencode claude-code --yes
python3 "$VIBE_SOURCE/scripts/check_skills.py" --skills-dir "$VIBE_CASE/.agents/skills"
```

Отдельные варианты проверяются в других чистых каталогах: `--skill run-task commit`,
затем та же установка с `--copy`. Для проверки кандидата перед обновлением CLI замени
закреплённую версию на нужную. Совместимость будущего `@latest` не предполагается заранее.

### Пробный процесс run-task

Независимый агент применил установленный `run-task` к отдельному временному Python-проекту
в доступной среде Codex. В задаче T01 требовалось исправить внутренний помощник медианы:
чётный список, сохранение исходного списка, понятная ошибка для пустого входа. Критерии
были заданы заранее; коммиты и внешние действия в этом эксперименте запрещены.

- Исполнитель и проверяющий запущены отдельно, без переноса истории исполнителя
  проверяющему. Проверяющий записал план от критериев до чтения реализации.
- Исполнитель исправил задачу; проверяющий добавил пять своих тестов. Общая команда
  `python3 -m unittest discover -s tests -v` обнаружила все девять тестов и завершилась успешно.
- Отдельный запуск `python3 -c` подтвердил три критерия наблюдаемым результатом.
- Сравнение состояния 165 файлов до/после проверяющего подтвердило сохранность кода
  функции, критериев приёмки и установленных скиллов. Изменены тесты, доказательства и журнал.
- Продолжение того же исполнителя по сохранённому идентификатору с уточняющим вопросом
  прошло успешно. Повторный цикл после неудачного ревью не проверялся: первый был успешен.
- Проектного мини-скилла проверок не было; команда взята из правил проекта. Это не стало
  препятствием. Ограничения роли проверяющего обеспечивались промптом и сравнением файлов.

Задача получила `review: auto` и `verify_attempts: 1`. Существующий контракт курса связывает
`done` с коммитом; из-за явного запрета коммита агент сохранил `in_progress` и записал причину
в журнал и доску. Исправление и проверка выполнены, ветка процесса с коммитом не проверялась.
Это известная особенность текущего формата задач, а не дополнительное разрешение на коммит.

Полный интерактивный прогон всех 31 скилла в каждом клиенте не выполнялся. Установка для
OpenCode проверена установщиком, сам OpenCode в окружении отсутствует. Эти результаты
подтверждают поставку ресурсов и один пробный процесс в Codex, а не одинаковое поведение
всех версий клиентов и моделей.
